# HR 展示指南

这份指南用于 3-5 分钟快速展示 ValueScope / NewsAnalysis。目标不是讲完所有细节，而是让对方看到：这是一个完整、有边界、有部署能力的工程项目。

## 展示前准备

1. 确认 Web 服务已启动。
2. 确认可以登录只读展示账号：

```text
账号：admin_view
密码：admin_view
```

3. 建议提前选一只资料较完整的股票，例如：
   - `300308.SZ` 中际旭创
   - `002714.SZ` 牧原股份
   - `600183.SH` 生益科技

## 3 分钟讲解稿

### 1. 项目定位

“这是我做的一个 A 股研究工作台。它不是单个分析脚本，而是一个包含数据采集、资料包管理、新闻库、后台调度和多 Agent 分析的完整 Web 系统。”

可展示首页顶部的 `ValueScope` 和 `Demo Tour`。

### 2. 股票检索

在左侧搜索框输入股票代码或名称。

讲法：

“这里支持代码、名称、拼音和首字母检索。选中股票后，系统会基于本地资料包和外部数据源组织数据。”

### 3. 数据资料包

点击“读取数据”或展示已有数据集。

讲法：

“每只股票会形成一个资料包，包括日行情、分钟行情、财务、估值、资金流、公告和新闻证据。我的设计目标是尽量抓到可获得的全部历史，而不是只抓最近三年。”

### 4. 多 Agent 分析

展示多 Agent 历史或运行多 Agent。

讲法：

“分析不是一个单 prompt，而是分成多个 Agent：估值、财务趋势、资金流、催化、风险审计等。最终报告会保留历史运行，后续可以复盘。”

### 5. 只读后台

用 `admin_view / admin_view` 登录 Admin Console。

讲法：

“这个账号是只读展示账号。它可以查看后台数据源、任务和新闻采集状态，但任何抓取、保存、删除、分析调用都会被后端拒绝，避免演示时误操作。”

建议展示页面：

- 运维状态：`/admin-ops.html`
- 数据源：`/admin-news.html`
- 新闻采集：`/admin-crawler.html`
- 行情补采：`/admin-market.html`
- 账户管理：`/admin-accounts.html`

## 技术亮点回答

如果 HR 或面试官问“这个项目难点是什么”，可以回答：

1. 多数据源兼容
   - 东方财富、AkShare、同花顺新闻、开盘啦、历史 Tushare 资料包都有不同格式。
   - 项目把它们统一成标准数据集，避免分析端感知数据源差异。

2. 采集和分析解耦
   - 新闻采集拆成独立 `NewsCrawler`。
   - 分析端只读 MongoDB 标准新闻文档，降低耦合。

3. 权限和安全
   - 管理员支持 TOTP。
   - 展示账号是后端强制只读，不只是前端隐藏按钮。
   - API key 和密码进入加密密钥库，不提交仓库。

4. 可部署性
   - 使用 Docker Compose 同时运行 Web、MongoDB 和 NewsCrawler。
   - 有部署脚本和 CI 工作流。

5. 面向真实使用的细节
   - 有只读运维状态、重 IO 互斥、任务日志、失败原因、重复抓取去重、手动补抓、空闲预抓和后台审计。

## 避免展开太深的点

- 不要在 HR 面前讲过多股票策略细节，容易偏离工程能力。
- 不要强调“投资建议”，建议说“数据辅助研究和分析报告生成”。
- 如果外部数据源偶发失败，直接说明“公开数据源存在限流或结构变化，所以系统保留失败记录和补抓入口”。

## 一句话收尾

“这个项目体现的是我把一个复杂数据分析想法产品化的能力：前端可演示、后端可运行、数据可追踪、权限可控制、部署可复现。”
