# ValueScope DataHub 项目简介

ValueScope DataHub 是一个面向 A 股研究的数据采集、治理和展示平台。它的核心目标是把“找股票数据、补行情、看新闻、查覆盖、看任务状态、确认数据是否可用”这些分散动作统一到一个可部署的 Web 系统里，并把整理后的数据供给下游 ValueScope 分析。

## 一句话定位

一个可演示、可部署、可扩展的 A 股数据中台：用自动化数据采集构建股票资料包、行情库和新闻库，再通过后台页面展示数据覆盖、质量和运行状态，为 ValueScope 分析提供可信输入。

## 主要能力

1. 股票检索与资料包
   - 支持代码、名称、拼音和首字母检索。
   - 尽量抓取可获得的全部历史数据，而不是只取最近几年。
   - 将行情、财务、估值、资金、公告、新闻等数据归档到本地资料包。

2. 行情与分钟数据补采
   - 支持手动补采指定股票分钟行情。
   - 支持空闲预抓：一段时间没有用户请求时，自动抓取尚未建立完整资料包的股票。
   - 后台可查看统一运维状态、任务进度、数据覆盖、日志入口和异常。
   - 重 IO 任务会自动互斥，避免全市场日 K、分时冷数据上传和空闲分钟预抓同时挤占服务器。

3. 新闻数据与新闻库
   - `NewsCrawler` 是独立服务，负责抓取新闻并写入 MongoDB。
   - DataHub 只读展示 `news.raw_articles`，并把标准化新闻供给 ValueScope 分析，保持采集、展示和分析边界清晰。
   - 后台“新闻数据”页只读展示新闻库、来源分布、采集运行和失败原因。

4. 数据展示与分析供给
   - 前端展示股票资料包、日 K、分时覆盖、新闻库、开盘啦行情和系统治理状态。
   - 保留历史多 Agent 报告读取和兼容入口，但 DataHub 的主职责是准备、校验和展示数据。
   - 下游 ValueScope 分析可以基于 DataHub 沉淀的数据版本、资料包和新闻证据继续生成分析结论。

5. 权限与只读模式
   - 管理员账号支持 TOTP 二次验证。
   - 管理员、只读管理员、注册用户和只读展示账号分离。
   - 访问与安全页面统一管理用户、邀请码、归档账号和系统凭据。
   - `admin_view` 只读账号可用于安全演示和只读巡检，所有写操作都会被后端拦截。

## 技术栈

- Backend: Python, `http.server` 自定义 Web 服务, MongoDB, Docker Compose
- Frontend: 原生 HTML/CSS/JavaScript，无重型前端框架
- Data: 东方财富、AkShare 候选源、同花顺新闻、开盘啦、通达信链路、历史 Tushare 资料包兼容
- AI: 历史 DeepSeek / 多 Agent 兼容链路，主要作为下游分析的数据消费入口
- Ops: 加密密钥库、任务审计、远程部署脚本、CI/部署工作流

## 工程亮点

- 不是“单次脚本”，而是长期运行的 Web + Scheduler + Crawler 系统。
- 新闻采集独立成 `NewsCrawler`，通过 `news.v1` 契约与 DataHub 展示层和下游 ValueScope 分析解耦。
- 2.0 将项目正式改名为 ValueScope DataHub，并把主线定位收拢为数据采集、数据治理、数据展示和下游 ValueScope 分析供给。
- 后台所有外部数据访问、数据抓取和模型兼容调用都要求审批，并写入审计记录。
- 只读展示账号在后端强制拦截 POST，避免演示时误触发真实任务。
- 股票来源被统一映射为标准数据类型，便于后续替换或增加 provider。

## 推荐查看路径

1. 打开首页和“项目介绍”，确认项目定位与核心流程。
2. 搜索一只股票，例如 `牧原股份` 或 `300308`。
3. 读取资料包，展示数据集、覆盖状态和图表。
4. 展示数据健康、冷备份状态和历史分析报告读取。
5. 用 `admin_view / admin_view` 进入后台，展示系统治理、股票数据、行情数据、新闻数据和访问与安全。
